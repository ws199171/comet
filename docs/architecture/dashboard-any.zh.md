# Comet Any 过程观测

启动 `comet dashboard`，在左侧选择 **Comet Any**。页面读取当前项目的 Creator 与应用 Run，从创作目标开始展示，不要求应用已经命名、编译或安装。

## 浏览过程

左栏将未生成应用的创作按目标显示；已生成应用按应用身份组织，并保留不同版本的创作和运行记录。卡片上的运行数统计已加载的顶层 Run，子流程从对应步骤进入。记录较多时可以继续加载列表和应用历史。

中央切换「创作过程」「应用运行」和具体记录。版本来自创作方案或 Run 保存的固定应用身份；切到新创作不会替换旧 Run 的版本。早期创作、停止创作、已交付及运行完成分别显示。

「当前工作」保留全部动作、用户确认、证据等待和子流程等待。`running` 表示动作已领取并等待宿主回传，不表示宿主当前在线。`unknown` 表示结果需要核对，不直接归为失败或重新执行。

步骤按已发生记录和就绪工作组织，不推测后续路径、耗时或完成百分比。同一步骤再次激活会保留独立记录；同一个动作的尝试、拒收回报和核对证据在右栏查看。未保存的旧结果不会补写。子流程使用 SDK 的真实引用，进入后读取其独立状态，并可返回父运行。

## 验证与产物

「版本与证据」区分本地校验、模型 Eval 和宿主验证。结果按固定应用内容关联；其他候选的报告保留，但不会作为当前版本通过的结论。没有独立宿主验证记录时保持「无记录」。本地校验或模型 Eval 通过不能推导真实宿主验收通过。

产物预览只接受当前记录中绑定的工件身份。文本预览限制大小，文件内容会与已记录摘要核对；内容变化或无法读取时保留明确提示。Dashboard 不接受任意文件路径，也不将 SDK 领取凭据返回浏览器。

## 刷新与异常

页面定期重读，也支持顶部手动刷新。查看历史时保留所选 Run、执行记录、标签页和展开项，新 revision 只提示有新进展；「回到当前工作」由用户主动定位。

暂时刷新失败时保留上次成功快照并显示读取时间。记录本身损坏时保留可识别的身份，隐藏不能信任的步骤和证据。单条坏记录不会遮住其他正常记录；数据源整体不可读和记录已移除也分别说明。分页游标绑定项目与查询结果，数据变化后重新读取当前页。

## 实现边界

Dashboard 通过 `workflow-creation`、`workflow-application` 的公开只读接口获取状态，复用 SDK 的存储校验与 Run 解析。观测不加载生成应用的执行模块，不恢复或迁移 Run，也不批准、重试、取消或推进流程。继续执行由 Agent 使用当前 Runtime 协议处理。

新存储位于用户 Comet 数据目录，并按 checkout / worktree 隔离；尚未迁移的旧项目状态可以只读发现。新旧存储出现相同 Run 的双重归属时明确报告，不能静默选择旧副本。

关联 Eval 仅在存在对应 Dashboard 记录时提供跳转；否则仍可查看绑定的报告。Native / Classic 链接要求当前项目存在匹配的 SDK 归属与领域记录。Creator 与它生成的应用按内容关联，二者不是 SDK 父子 Run。
